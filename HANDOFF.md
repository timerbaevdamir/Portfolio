## Что стоит сейчас

**Стиль.** Нейтральный графит без коричневого, Google Sans 400–700 через
Google Fonts с кириллицей. Общие кнопки и подписи без моноширинного шрифта
и капса. Палитра и типографика одинаковые на витрине и внутри кейса.
Напротив аватара — переключатель светлой и тёмной темы; на мобильном он
в шапке справа. Выбор сохраняется в localStorage, применяется до первого
отображения и сохраняется при переходе в кейс. GitHub и LinkedIn имеют
второстепенный фон в обеих темах.

**Витрина.** Слева фиксированный профиль шириной 300–320 px: фото, имя,
роль, о себе, Wildberries и coffeemap.ru, контакты. Справа панель с сеткой
карточек по две в ряд. Карточки со скруглениями, фоном `ground` без рамки и состояниями
hover/focus; живые превью изолированы. Телефон в превью показан с отступами.
На мобильном шапка с именем закреплена, сетка при скролле накрывает профиль.

**Кейс.** Рейл (✕ домой, ↑ n/N ↓), колонка описания и сцена. На мобильном
кнопки «Прототип / Описание». В сцене переключатель с иконками устройств
(на узкой сцене только иконки с доступными названиями), домен и «Открыть».
Плашка переключателя, адрес и «Открыть» выровнены по внешней высоте
44 px; при увеличении текста строка растёт целиком. У «Открыть» нет иконки.
Выбранные сегменты в светлой теме белые; кнопки рейла круглые, разделители
описания ослаблены. Масштабирование iframe и сброс viewport по ключу
проекта сохранены.

**Три проекта:** `job-board` (живой, телефон + десктоп), `ui-agent` (живой,
только десктоп), `coffee-map` (обложкой, см. ниже).

## Открытое

### 1. Опыт в боковой колонке пуст

`SITE.experience` — пустой массив, секция не рендерится, пока в нём ничего нет.
Оставлено пустым намеренно: работодатель — факт о человеке, и он появляется на
публичной странице, только если человек его написал, а не потому что его можно
угадать по почте в гите. **Заполнить должен автор.**

### 2. Кофейная карта показана обложкой

На витрине — оформленная обложка с иконкой, доменом и подписью «На отдельном
сайте»; в кейсе — название, причина из `embed` и ссылка. Скриншот не добавлен.
Если позже понадобится: возвращать `poster` вместе с отрисовкой и в `Thumb`,
и в `Cover`.

### 3. API Кофейной карты падает — диагностика проведена, чинить не здесь

`coffeemap.ru/api/coffee-shops` отдаёт 500 с `{"error":"TypeError: fetch
failed"}`. Портфолио ни при чём: при прямом открытии сайта то же самое.

Уже проверено, **перепроверять не нужно**:

| Что | Результат |
|---|---|
| Проект Supabase `zofruwsqkjnperxltgrt` | `ACTIVE_HEALTHY` |
| REST снаружи | 200 за 2.1 с, данные отдаёт |
| Вью `api_coffeeshops_full_view` | существует |
| Сам запрос в БД | 73 мс, 539 кофеен |
| Три запроса подряд к сайту | 200 за 20.7 с, потом 500 за 10.6 с, 500 за 10.6 с |

Ключевое: **иногда проходит**. Значит переменные окружения целы — неверный URL
или ключ падали бы всегда. Повторяющиеся 10.6 с — дефолтный `connectTimeout`
undici, то есть соединение не открывается вовсе. Сайт живёт на Yandex.Cloud
(RU, 93.77.183.4), Supabase за зарубежным CDN; дальше это догадка, но
связность, судя по цифрам, плавает.

Чинится в репозитории `~/Documents/coffee-map-app`, в
`app/api/coffee-shops/route.ts`: сейчас первая же неудача уходит в `catch` и
возвращает 500, ретрая нет, а кэш живёт в памяти процесса и пуст после
рестарта. Один ретрай плюс отдача устаревшего кэша при сбое закрыли бы ровно
этот сценарий.

Когда устаканится — вернуть `embed: true` у `coffee-map`. Вьюпорты для него
оставлены на месте, фрейм вернётся целиком.

### 4. Кейсы-видео и гифки — отложено автором

Часть будущих работ это не сайты, а записи экрана. Договорённость: **займёмся
потом.** Рекомендация в силе — хранить в `public/`, брать MP4, а не GIF, и
описать медиа размеченным объединением вместо флага:

```ts
type Media = { kind: "live" } | { kind: "video"; src: string } | { kind: "link" }
```

Открытый вопрос, который надо будет задать: одно видео на кейс или своё на
каждый раздел.
